# Sketch 002: Supply Add — Synthesis

## Design Question
Does the synthesized table layout with auto-calc need and all-visible fields feel right for transcribing colour lists?

## How to View
open .planning/sketches/002-supply-add-synthesis/index.html

## What Changed from Sketch 001
Synthesis of feedback on all three original variants:
- **Table layout from C** — compact single-line rows, spreadsheet feel
- **All fields visible at once from A** — no progressive reveal (B felt too slow)
- **No "have" in the add row from B** — you're transcribing, not shopping
- **Auto-calculated need** — stitches entry triggers skein calculator to pre-fill need
- **State toggles removed** — always show all added colours
- **Fixed alignment** — add row inputs properly align under column headers

## Variants

- **Synthesis: Table + Auto-Calc** — Full table with separate Need and Have columns. Add row shows Code, Stitches, Need (auto-calculated). Need shows a sparkle indicator when auto-filled, disappears if you manually override. 8 pre-populated items to evaluate density.

- **Refinement: Ultra-Compact** — Same interaction model but tighter: smaller swatches, abbreviated labels, Need/Have merged into one column (2/1 format). Compare vertical density at 8+ items.

## What to Look For
1. **Add row alignment** — do the inputs sit cleanly under the column headers?
2. **Auto-calc flow** — type stitches, see need auto-fill. Does that feel helpful or surprising?
3. **Density** — with 8 items showing, does the table feel scannable?
4. **Synthesis vs Ultra-Compact** — is the extra compactness worth the trade-off in readability?
5. **Keyboard flow** — code → Enter → stitches → Tab → need (auto-filled) → Enter to add

| Token | Value | Usage |

| sm | 8px | Compact element spacing, gap-2, p-2 |
| md | 16px | Default element spacing, p-4, gap-4 |
| lg | 24px | Section padding, py-6, gap-6 |
| xl | 32px | Layout gaps, gap-8 |
| 2xl | 48px | Major section breaks, py-12 |

Exceptions:
- Touch targets: 44px minimum on increment/decrement buttons (existing `min-h-[44px] min-w-[44px]` pattern on QuantityControl)

## Interaction Contracts

### Search Behavior

| Behavior | Specification |
|----------|---------------|
| Debounce | 150ms debounce on keystroke using `useDeferredValue` (React built-in, no new dependency). Matches the instant-feel pattern used in genre-list.tsx where `useState` + `useMemo` filtering is synchronous. |
| Clear | X button appears when input is non-empty. Click or Escape clears input and restores full list. |
| Scope | Project search filters the project list in By Project view and the underlying project selection pool in By Supply view. Supply search only filters within the By Supply view (D-05). |
| Persistence | Search terms are ephemeral -- not persisted to localStorage. Cleared on page navigation. |

### Status Group Collapsibility (D-02, D-03, D-04)

| Behavior | Specification |
|----------|---------------|
| Default state | All groups expanded on initial render |
| Collapse mechanism | Click group header chevron or header area to toggle. Simple `display: none` on collapse body -- no animation needed (keeping it simple per Claude's discretion). |
| Group order | Fixed: KITTING, IN_PROGRESS, ON_HOLD, UNSTARTED, KITTED, FINISHED, FFO (D-03: workflow progression, "Kitting" first since 75+ projects are in kitting) |
| Empty groups | Groups with 0 projects (or 0 search matches) are not rendered. Auto-hide, not collapsed (D-04). |
| Collapse persistence | Collapse state stored in component `useState` only -- resets on page load. Not worth persisting for this interaction. |

### Selection with Filtering (D-07, D-08, D-09, D-10)

| Behavior | Specification |
|----------|---------------|
| Select All (global) | When search is active: selects only visible/filtered projects. When no search: selects all projects (D-07). |
| Selection persistence through search | Searching does not deselect hidden projects. Selection is maintained as a `Set<string>` independent of search filter (D-08). |
| Iterative selection | User can search "dragon", select matches, clear search, search "fairy", select matches -- all selections accumulate (D-08). |
| Selection counter | Shows "3 of 12 visible selected (5 total selected)" when search is active and total !== visible selected count. Shows "5 of 48 projects selected" when no search is active (D-09). |
| Group select | Each status group header has a "Select all" link. Clicking selects all projects in that group that are currently visible (respects active search filter) (D-10). |

### Supply Search in By Supply View (D-05, D-06)

| Behavior | Specification |
|----------|---------------|
| Match fields | Brand name, color code, color name. Case-insensitive substring match. NOT project names. |
| Section auto-hide | Thread/Bead/Specialty/Fabric sections with zero matches hide completely (D-06). |
| No-results state | When all sections are hidden by search: show EmptyState with Search icon, "No supplies match your search" heading, and "Try a different search term" description. |

## Layout Contract

### Search Input Placement

```
[ShoppingForBar - sticky header with selected project pills]

[Search input _____________________________ (x)]  <-- Full width above tabs
  
[Projects tab] [Shopping List tab]

[By Project / By Supply Type toggle]

[Status groups with project cards...]
```

The search input sits between the ShoppingForBar and the Tabs component. It is always visible regardless of which tab or view mode is active. It shares a row with nothing -- full width of the content area.

### Status Group Layout (By Project View)

```
[v] Kitting (12)                    [Select all]
  [checkbox] [img] Project Name [Kitting]  [>]
  [checkbox] [img] Project Name [Kitting]  [>]
  ...

- Group header: flex row with chevron, status dot + label, count badge, and right-aligned "Select all" link
- Group body: existing ProjectAccordion card layout, unchanged
- Gap between groups: 16px (gap-4)

  [supply rows...]

  [supply rows...]
```

The supply search input appears at the top of the By Supply view content, below the view toggle. It is only visible when "By Supply Type" is the active view mode.

## Performance

| Concern | Approach |
|---------|----------|
| 75+ projects rendering | Status grouping + collapsible sections reduces visible DOM. No virtualization needed -- grouping naturally segments the list. Search further reduces rendered count. |
| Filter computation | `useMemo` with `searchQuery` dependency. String `.toLowerCase()` matching is O(n) and fast for < 500 items. |
| Debounce approach | `useDeferredValue` for search input -- React will defer re-rendering the filtered list during typing, keeping the input responsive. No external debounce library. |
| Re-render scope | Search state lives in ShoppingCart. Only ProjectAccordion or SupplyOverview re-renders on search change, not the entire page. |

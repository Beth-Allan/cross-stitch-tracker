5. **Segmented toggle active state** -- `bg-primary text-primary-foreground` on selected type button
6. **SVG donut complete state** -- full ring in primary (emerald-600) when have >= need
7. **Editable cell hover indicator** -- subtle primary-tinted background on clickable cells

## Layout Contract

### Table structure

```
section-card (rounded-lg border bg-card p-0 overflow-hidden)
  table.supply-table (w-full, border-collapse, table-layout: fixed)
    thead
      tr: [Colour 44%] [Stitches 14%] [arrow 24px] [Need 13%] [Have 10%] [Status 6%] [Del 32px]
    tbody
      tr.add-row (persistent, always visible, green tint + primary bottom border)
      tr.section-divider "Thread" (icon + label + count badge) -- hidden when 0 items
      tr.data-row * N (thread items, newest first within section)
      tr.section-divider "Beads" (icon + label + count badge) -- hidden when 0 items
      tr.data-row * N (bead items)
      tr.section-divider "Specialty" (icon + label + count badge) -- hidden when 0 items
      tr.data-row * N (specialty items)
  footer (px-4 py-3, border-t, flex justify-between)
    left: "N colours added" / "Total: N skeins needed"
    right: keyboard hints
```

### Column widths (table-layout: fixed)

| Column | Width | Content |
|--------|-------|---------|
| Colour | 44% | Swatch (16x16) + code (mono 12px bold) + name (12px muted, ellipsis) |
| Stitches / Qty | 14% | Number (add row: input, data row: editable click cell) |
| Arrow | 24px fixed | Right arrow icon (shows calc direction for threads, hidden for specialty) |
| Need | 13% | Number + unit label ("sk" / "pkg" / "item"), auto-calc sparkle for threads |
| Have | 10% | Number (editable click cell) |
| Status | 6% | 16x16 SVG donut |
| Delete | 32px fixed | Trash2 icon, opacity 0 until row hover |

### Column adaptation per supply type

| Type | Stitches column | Arrow | Need unit | Need default | Auto-calc |
|------|----------------|-------|-----------|--------------|-----------|
| Thread | Stitches (editable) | Visible (arrow-right) | "sk" (skeins) | Auto from stitches, or 1 | Yes |
| Bead | Bead count (editable) | Visible (arrow-right) | "pkg" (packages) | 1 | No |
| Specialty | Hidden (dash or empty) | Hidden | "item" | 1 | No |

## Interaction Contract

### Keyboard flow (add row)

1. **Focus search input** -- type supply code/name
2. **Autocomplete appears** -- arrow keys navigate, Enter selects, Escape closes
3. **After selection** -- cursor auto-advances to Stitches field (threads/beads) or Need field (specialty)
4. **Stitches/Qty field** -- Enter commits row (fast path), Tab advances to Need for manual override
5. **Need field** -- Enter commits row
6. **After commit** -- row animates into correct section, search input refocuses, type toggle stays sticky
7. **Escape at any point** -- resets add row fields to empty, refocuses search

### Segmented type toggle

- Three buttons: Thread (default), Beads, Specialty
- **Sticky between adds** -- user selects Beads once, then adds multiple beads without re-selecting
- Visual: active button gets `bg-primary text-primary-foreground`, inactive gets `bg-card text-muted-foreground`
- Toggle changes which fields appear in the add row and which autocomplete source is queried

### Inline editing (data rows)

- Click any editable cell (stitches, need, have) to enter edit mode
- Cell transforms to a compact number input (`w-12 rounded border px-1.5 py-0.5 text-center text-sm`)
- **Enter** saves and exits edit
- **Escape** reverts to original value and exits edit
- **Blur** saves if value is valid, reverts if invalid
- Hover on editable cells shows subtle primary-tinted background to indicate clickability

### Delete

- Trash2 icon at 16x16, opacity 0 by default
- `tr:hover .del-btn { opacity: 1 }` reveals on row hover
- Click deletes immediately -- no confirmation modal (CONTEXT decision D-04 equivalent; REQUIREMENTS SUPENT-04)
- Delete button hover: `text-destructive bg-destructive/8`

### Autocomplete (portal)

- `position: fixed` with JS-calculated coordinates from `getBoundingClientRect()` on the search input
- `width: max(320px, input width)`
- `max-height: 240px`, `overflow-y: auto`
- `z-index: 9000` (above all table content)
- `border-radius: 8px`, `shadow-lg`, `border border-border`
- Items show: swatch + code + name
- Already-added items: disabled appearance (`opacity-50`, "Added" text label, not clickable)
- Zero results with search text: show "+ Create [search text]" option (triggers InlineCreateDialog)
- Keyboard: arrow up/down to navigate, Enter to select, Escape to close

### New row animation

```css
@keyframes slideIn {
  from { opacity: 0; transform: translateY(-6px); }
  to { opacity: 1; transform: translateY(0); }
}
```
Duration: 0.2s, easing: ease. Applied to newly added data rows.

## SVG Donut Specification

16x16 viewBox, `r=6` circle centered at (8,8), `stroke-width: 2`, `fill: none`.

| State | Ring stroke | Calculation |
|-------|-----------|-------------|
| Empty (have = 0) | `border-muted` only (background ring) | No foreground arc |
| Partial (0 < have < need) | Background: `border-muted`, Foreground: `text-warning` (amber) | `stroke-dasharray: 37.7`, `stroke-dashoffset: 37.7 * (1 - have/need)` |
| Complete (have >= need) | Background: `border-muted`, Foreground: `text-primary` (emerald) | Full ring, no dashoffset |

Additional:
- `transform="rotate(-90 8 8)"` on foreground circle so arc starts at 12 o'clock
- `stroke-linecap="round"` on foreground circle for rounded arc ends
- `<title>` element for accessibility: "X of Y" (e.g., "1 of 2")

## States

### Loading state
- Skeleton rows in table body: 3 rows with pulsing `animate-skeleton-pulse` bars
- Add row remains interactive during skeleton (search input enabled)

### Empty state (no supplies at all)
- Section card with table headers visible
- Add row visible and ready for input
- Below add row: `EmptyState` component with CircleDot icon, "No supplies added yet", "Start typing a supply code above to add your first colour."

### Empty section (e.g., no beads yet)
- Section divider hidden entirely when section has 0 items
- Sections appear only when their first item is added

### Error state (adapter failure)
- Toast notification via sonner: "{action} failed. Try again."
- Row reverts to previous value on update failure
- Row remains visible on delete failure

## Adapter Interface (SupplyTableAdapter)

The table is data-source agnostic. It receives an adapter that handles persistence:

```typescript
interface SupplyTableAdapter {
  addThread(threadId: string, stitchCount: number, need: number): Promise<Result>;
  addBead(beadId: string, quantity: number, need: number): Promise<Result>;
  addSpecialty(itemId: string, need: number): Promise<Result>;
  updateQuantity(type: SupplyType, junctionId: string, field: string, value: number): Promise<Result>;
  remove(type: SupplyType, junctionId: string): Promise<Result>;
  searchSupplies(type: SupplyType, query: string): Promise<SupplySearchResult[]>;
  createSupply(type: SupplyType, data: CreateSupplyData): Promise<SupplySearchResult>;
}
```

Phase 10 builds a **local-state adapter** (in-memory, for story/test isolation).
Phase 11 adds a **server-action adapter** (wired to existing supply CRUD actions).
Phase 13 adds a **creation-flow adapter** (buffers changes until two-phase save).

## Accessibility

- Table uses semantic `<table>`, `<thead>`, `<tbody>`, `<th scope="col">`, `<td>` elements
- SVG donuts include `<title>` for screen readers ("X of Y")
- Autocomplete uses `role="listbox"` + `role="option"` with `aria-activedescendant` for keyboard navigation
- Segmented type toggle uses `role="radiogroup"` + `role="radio"` with `aria-checked`
- Delete buttons have `aria-label="Remove {supply name}"`
- Editable cells have `aria-label="{column name} for {supply code}"`
- Focus management: after adding a row, focus returns to search input
- `prefers-reduced-motion`: disable slideIn animation (already handled in globals.css pattern)

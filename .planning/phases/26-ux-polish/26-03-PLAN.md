    The root cause: `supply-catalog.tsx` initializes `viewModes` with defaults in `useState` (line 189-195), then reads localStorage in a `useEffect` (line 198-210). The `useEffect` runs after the first paint, causing a flash when the stored preference differs from the default.

    **Fix:** Move the localStorage read INTO the `useState` initializer function so it runs synchronously before first paint.

    1. In `supply-catalog.tsx`, replace the current `useState` initializer (lines 189-195):
       ```typescript
       const [viewModes, setViewModes] = useState<Record<SupplyTab, ViewMode>>(() => {
         const modes = { ...DEFAULT_VIEWS };
         // URL param takes precedence for the specified tab
         if (initialView) {
           modes.threads = initialView;
         }
         // Read localStorage synchronously to prevent flash
         if (typeof window !== "undefined") {
           for (const tab of TAB_CONFIG) {
             if (tab.key === "threads" && initialView) continue;
             const stored = localStorage.getItem(STORAGE_KEYS[tab.key]);
             if (stored === "grid" || stored === "table") {
               modes[tab.key] = stored;
             }
           }
         }
         return modes;
       });
       ```

    2. Remove or simplify the `useEffect` that previously read localStorage (lines 198-210). Since localStorage is now read in the initializer, the useEffect is no longer needed for initial state. If the useEffect does other work (like syncing on tab change), keep that portion. If it only reads localStorage on mount, remove it entirely.

    3. The `typeof window !== "undefined"` guard ensures SSR compatibility -- localStorage is not available during server rendering. During SSR, defaults are used. On client hydration, the initializer runs with localStorage access, so the first paint matches the stored preference.

    4. This is safe because `useState` initializer functions run synchronously during the initial render (before paint), so there's no flash.

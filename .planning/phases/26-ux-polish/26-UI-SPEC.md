## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, `gap-1` / `p-1` |
| sm | 8px | Compact element spacing, `gap-2` / `p-2` |
| md | 16px | Default element spacing, `gap-4` / `p-4` |
| lg | 24px | Section padding, `gap-6` / `p-6` |
| xl | 32px | Layout gaps, `gap-8` / `p-8` |
| 2xl | 48px | Major section breaks, `gap-12` / `py-12` |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Touch targets: 32px minimum for interactive elements (`h-8 w-8` for icon buttons like focal point trigger)
- Supply table cell padding: 5px vertical (`py-[5px]`) per sketch findings density convention

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` (stone-50 light / stone-950 dark) | Page backgrounds, surfaces |
| Secondary (30%) | `bg-card` (white light / stone-900 dark) | Cards, dialog backgrounds, input backgrounds |
| Accent (10%) | `bg-primary` / `text-primary` (emerald-600 light / emerald-500 dark) | Primary CTA buttons, focus rings, active nav, progress bars |
| Destructive | `bg-destructive` / `border-destructive` (red-600 light / red-500 dark) | Delete actions, validation error borders, rejected input flash |
| Success | `bg-success-muted` / `text-success-muted-foreground` | Kitting 100% badge background + text |
| Warning | `bg-warning-muted` / `text-warning-muted-foreground` | Kitting in-progress badge background + text |
| Selected | `bg-selected` / `text-selected-foreground` / `border-selected-border` | Shopping-for bar pills, active selection states |
| Progress | `text-progress-foreground` / `bg-progress` | Kitting bars, percentage labels |

Accent reserved for: Primary action buttons (Save, Create & Add), focus rings on inputs, active navigation indicators, progress bar fills, link hover states. Never used for decorative backgrounds or borders.

## Component Interaction Contracts

### UX-01: SearchToAdd Keyboard Highlight

| Property | Value |
|----------|-------|
| Trigger | Arrow key press (ArrowDown/ArrowUp) sets `hasUsedArrowKeys = true` |
| Visual | Highlight class (`bg-accent`) only applied when `hasUsedArrowKeys && index === highlightIndex` |
| Reset | `hasUsedArrowKeys` resets to `false` on: new search query, mouse click on item, Escape |
| Initial state | No highlight visible on dropdown open (highlightIndex stays -1 until arrow key) |
| Mouse hover | Mouse hover does NOT set `hasUsedArrowKeys` -- mouse and keyboard highlights are independent |

### UX-02: Card Row ARIA

| Component | Pattern | Changes |
|-----------|---------|---------|
| `DesignerRow` / `DesignerCard` | Flat DOM: `<Link>` for name + sibling action buttons | Add `role="group"` + `aria-labelledby={nameId}` to container. Add `aria-label` to edit/delete buttons: "Edit {name}" / "Delete {name}" |
| `GenreRow` / `GenreCard` | Same as designer | Same treatment |
| `GalleryCard` | `<Link>` wraps name only | Extend `<Link>` to also wrap the image (larger click target). No nested interactives -- no action buttons in gallery cards |
| `BucketProjectRow` | Entire `<Link>`, no nested interactives | No changes needed (already correct) |

### UX-03: EditableNumber Rejection Feedback

| State | Visual | Duration |
|-------|--------|----------|
| Invalid draft (while typing) | `border-destructive bg-destructive/10` on input | Persistent while draft is invalid |
| Rejection flash (on blur/Enter with bad value) | `border-destructive` + `animate-shake` on read-mode button | 600ms, then revert to normal styling |
| Valid state | `border-primary` (existing) | Immediate |

Implementation: Both variants (supply-table `editable-number.tsx` and charts `editable-number.tsx`) get identical treatment. Add `isInvalid` derived state from draft parsing. On rejection, set `showRejection = true` with 600ms timeout.

### UX-04: Supplies Page First-Load Flash

| Property | Value |
|----------|-------|
| Root cause | `localStorage.getItem()` runs in `useEffect` (client-only), causing view mode to snap from default to stored preference |
| Fix approach | Read `?view=` search param server-side (already partially done for threads tab). For other tabs, show loading skeleton during `useEffect` localStorage read, OR initialize state from a default that matches the most common case (table view) |
| Skeleton | Use existing `animate-skeleton-pulse` class on a placeholder matching the table layout dimensions |
| Duration | One render cycle -- skeleton shows only until `useEffect` fires |

### UX-05: Kitting Label Three-State Copy

| Condition | Label Text | Badge Style |
|-----------|-----------|-------------|
| `kittingPercent === 0` | "Not kitted" | `text-muted-foreground` (neutral -- no progress implied) |
| `kittingPercent > 0 && < 100` | "Kitting" | `text-warning-muted-foreground` (existing amber) |
| `kittingPercent === 100` | "Fully kitted" | `text-success-muted-foreground` (existing green) |

Applies to: desktop kitting label in `whats-next-tab.tsx` line 184. Mobile compact badge (percentage-only) unchanged.

### UX-07: Supply Table Commit Button

| Property | Value |
|----------|-------|
| Icon | `Check` from lucide-react (16px, `h-4 w-4`) |
| Position | Right side of add row, after quantity fields, before the row's trailing edge |
| Styling | `text-primary hover:bg-primary/10 rounded p-1 transition-colors` |
| Behavior | Triggers same flow as Enter key -- commits selected supply to table |
| Visibility | Only visible when a supply is selected (item picked from autocomplete) |
| Disabled state | Hidden when no supply is selected (not disabled -- hidden) |
| Aria | `aria-label="Add supply to table"` |
| Size | 28px touch target (`p-1` + 16px icon) |

### UX-08: InlineCreateDialog Contextual Labels

Dialog title also contextualizes: "Create Thread" / "Create Bead" / "Create Specialty Item".
Dialog description: "Create a new {typeLabel} and add it to the table." (existing pattern, already contextual).

### UX-09: BucketProject Focal Point

| Property | Value |
|----------|-------|
| Data source | `focalPointX` / `focalPointY` from chart query (already in schema) |
| Utility | `getObjectPositionStyle()` from `src/lib/utils/focal-point.ts` |
| Application | `style={{ objectPosition: getObjectPositionStyle(focalPointX, focalPointY) }}` on the `<img>` element in `bucket-project-row.tsx` |
| Fallback | When focal point is null, use `object-position: center` (default behavior, no change) |
| Query change | `BucketProject` type needs `focalPointX?: number, focalPointY?: number` fields; dashboard query must select these columns |

### UX-10: Focal Point Action Bar Repositioning

| Property | Before | After |
|----------|--------|-------|
| Position | `absolute bottom-0 right-0 left-0 z-20` inside banner container | Sibling `<div>` below the banner container, in normal document flow |
| Architecture | Single `FocalPointEditor` component | Split into `FocalPointClickArea` (overlay inside banner) + `FocalPointActionBar` (sibling below banner) |
| Styling | `border-t bg-card/90 backdrop-blur-sm rounded-b-lg p-2` | Same visual treatment: `border-t border-border bg-card/90 backdrop-blur-sm p-2` with `animate-in slide-in-from-bottom-1` |
| Image click area | Bottom ~25% blocked by action bar | 100% of image surface clickable |
| Edit mode trigger | Button stays `absolute top-2 right-2 z-10` inside banner | Unchanged |

### UX-11: Fabric Matching Null FabricCount

| Property | Value |
|----------|-------|
| Current behavior | `null` fabricCount short-circuits matching, returns zero candidates |
| Fixed behavior | When `fabricCount` is null, skip fabric count comparison filter -- match on other criteria only (fabric type, color, etc.) |
| Effect | Projects without assigned fabric see all fabric candidates instead of zero |

### UX-12: ThreadInsightList Visual Alignment

| Property | Before | After |
|----------|--------|-------|
| Rank numbers | None | `{index + 1}.` in `text-muted-foreground w-5 font-mono text-xs tabular-nums` (matches DesignerInsightList and GenreInsightList) |
| Interactive styling | None (no hover, no cursor-pointer, no links) | No change -- stays non-interactive per D-13, D-14 |
| Layout | `flex items-center justify-between py-2` | Same structure, rank number added to left side |

### UX-13: Cover Image Preview Dynamic Aspect Ratio

| Property | Before | After |
|----------|--------|-------|
| Container height | Fixed `h-48` (192px) | Dynamic: `aspect-ratio` CSS property from image natural dimensions |
| Fallback | n/a | `h-48` skeleton while image loads (before `onLoad` fires) |
| Max height | none | `max-h-72` (288px) to prevent tall images from dominating the form |
| Object fit | `object-contain` | `object-contain` (unchanged) |
| Implementation | Static container | Add `onLoad` handler: capture `naturalWidth/naturalHeight`, set container `style={{ aspectRatio: \`\${w}/${h}\` }}` |
| Hero banner | `object-contain` + blur fill | No change (D-12: intentional design from Phase 17) |

### UX-14: What's Next Gallery Card Styling

| Property | Before (What's Next card) | After |
|----------|--------------------------|-------|
| Image | 48x48 `rounded-md object-cover` thumbnail | Match gallery card: taller image area with `rounded-t-lg`, aspect-[4/3] container |
| Layout | Horizontal row (`flex items-center gap-3`) | Vertical card stack matching `GalleryCard` structure |
| Name | `text-sm font-semibold font-heading` | Same typography, add underline-on-hover matching gallery card pattern |
| Hover | `group-hover:text-emerald-700` (hardcoded) | `group-hover:text-selected-foreground` (semantic token) |
| Card container | No card wrapper | `bg-card border-border rounded-lg border` |
| Status badge | Hidden on mobile, shown on desktop | Shown in card footer area (matching gallery card status footer pattern) |
| Grid | Single column list | Responsive grid: `grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 gap-4` |

Note: The current hardcoded `group-hover:text-emerald-700 dark:group-hover:text-emerald-400` in both `whats-next-tab.tsx` and `bucket-project-row.tsx` should be replaced with `group-hover:text-selected-foreground` for semantic token consistency (aligns with QUAL-08 pattern from Phase 24).

## Accessibility Contract

| Requirement | ARIA Pattern | Test Approach |
|-------------|-------------|---------------|
| Card row grouping (UX-02) | `role="group"` + `aria-labelledby` on container; `aria-label` on action buttons | Query `role="group"`, verify `aria-labelledby` references visible name element |
| Keyboard highlight (UX-01) | `aria-activedescendant` points to highlighted item only when `hasUsedArrowKeys` is true | Simulate ArrowDown, verify `aria-activedescendant` updates; verify no `aria-activedescendant` on initial open |
| Focal point (UX-10) | `role="button"` + `aria-label="Click to place focal point"` on click area; keyboard Enter places at center | Existing pattern, preserved in split |
| EditableNumber (UX-03) | `aria-invalid="true"` during invalid draft state | Query input, verify `aria-invalid` attribute presence during invalid state |
| Commit button (UX-07) | `aria-label="Add supply to table"` | Query by aria-label, verify click triggers add |

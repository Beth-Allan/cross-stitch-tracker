## Component Interaction Contracts

### BUG-01: Designer Inline Creation Dialog

| Property | Value |
|----------|-------|
| Trigger | `SearchableSelect.onAddNew` callback in the Designer field |
| Dialog component | Existing `InlineDesignerDialog` -- no new component |
| Wiring pattern | Two `useState` vars: `designerDialogOpen` (boolean) + `designerDialogInitialName` (string). Identical to `InlineNameDialog` pattern used for storage locations (lines 166-169 of `chart-merged-form.tsx`) |
| Dialog position | Controlled dialog as JSX sibling to `SearchableSelect`, not nested inside it |
| Title | "Add New Designer" (existing copy in `inline-designer-dialog.tsx`) |
| Fields | Name (required, autoFocus) + Website (optional, hint: "Optional") |
| Submit label | "Add Designer" (existing) / "Adding..." (pending state) |
| Cancel | "Cancel" ghost button |
| Error display | Inline error text below Name field via `FormField` error prop |
| Post-submit | Dialog closes, new designer auto-selected in SearchableSelect |
| initialName sync | Search term from SearchableSelect populates Name field when dialog opens |

No visual changes to the dialog component itself. The contract is purely about wiring the existing component into the form.

### BUG-02: Designer Field Tab Focus

| Property | Value |
|----------|-------|
| Expected behavior | Tab into the Designer `SearchableSelect` field, then typing immediately filters options |
| Current behavior | Focus lands on the trigger button but typing does not filter (Popover/Command focus delegation issue) |
| Fix approach | At Claude's discretion -- likely needs focus forwarding from `PopoverTrigger` to `CommandInput` when Popover opens |
| Visual impact | None -- fix is purely interaction/focus management |
| Test approach | Simulate Tab into field, type characters, verify filtered results appear |

### BUG-04: Designer Detail Thumbnails

| Property | Value |
|----------|-------|
| Current rendering | `chart.coverThumbnailUrl` in a `h-10 w-10 rounded-lg object-cover` container with `getObjectPositionStyle()` for focal point |
| Issue | Wrong or missing thumbnails on designer detail page |
| Visual contract | No changes to thumbnail styling -- fix is in data layer (query/join) |
| Existing thumbnail spec | 40x40px rounded-lg container, `object-cover`, focal point applied via inline `style` |
| Placeholder | `bg-muted` 40x40 container with `ImageIcon` in `text-muted-foreground/40` |

### BUG-05: Stitch Count Supply Total Hint

| Property | Value |
|----------|-------|
| Element | New read-only hint text below or adjacent to the Total Stitch Count input field |
| Content | "Supply total: {N} stitches" where N is the sum of all supply `stitchCount` values |
| Visibility | Only shown when at least one supply has a non-zero `stitchCount` |
| Typography | `text-xs text-muted-foreground` (12px, regular weight, muted color) |
| Layout | Below the existing stitch count hint text, inside the same `FormField` area |
| Icon | `Info` from lucide-react at `h-3 w-3 text-muted-foreground` inline with text (optional, at executor discretion) |
| Behavior | Display-only -- no click action, no override of manual value |
| Both modes | Visible in create mode (when supply panel has entries) and edit mode (when project has linked supplies) |
| Not shown when | Supply total is 0, or no supplies are linked |
| Formatting | Number uses `toLocaleString()` for thousands separators (matches existing `effectiveCount.toLocaleString()` pattern) |

Rationale (D-04, D-05): The manual `totalStitchCount` field stays authoritative. Partial supply entry (common with 50+ color charts) would produce misleading size categories if auto-summed. The hint is purely informational.

### BUG-06: Skeins Need Column Width

| Property | Before | After |
|----------|--------|-------|
| Need column width | `style={{ width: "13%" }}` | `style={{ width: "16%" }}` |
| Colour column width | `style={{ width: "44%" }}` | `style={{ width: "41%" }}` |
| Other columns | Unchanged | Unchanged |
| Total | 44 + 14 + 24px + 13 + 10 + 6 + 32px = ~87% + 56px | 41 + 14 + 24px + 16 + 10 + 6 + 32px = ~87% + 56px |

The 3% moves from Colour to Need. The Colour column has room to spare (truncates long names with `truncate` class). The Need column needs space for: editable number (up to 3 digits) + unit label ("sk"/"pkg"/"item") + Sparkles icon (12px).

Source: D-07 from CONTEXT.md. Exact percentage at executor discretion (D-07 says "widen", 16% is the recommended value based on content analysis).

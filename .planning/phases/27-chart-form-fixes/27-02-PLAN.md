The rendering in `designer-detail.tsx` (lines 301-315) correctly uses `chart.coverThumbnailUrl`.

    Investigation steps:
    1. Check if the issue is a **thumbnail generation race condition** — cover images uploaded but thumbnails not yet generated. Look at `upload-actions.ts` to understand when `coverThumbnailUrl` gets set. If thumbnail generation happens asynchronously (after the chart is created), there's a window where `coverThumbnailUrl` is null even though `coverImageUrl` exists.

    2. If the bug is a **thumbnail generation gap**, the fix is to fall back to `coverImageUrl` when `coverThumbnailUrl` is null but `coverImageUrl` exists. This requires:
       - Adding `coverImageUrl` to the `getDesigner` query's `charts.select` (add `coverImageUrl: true` to the select object at line ~101)
       - Adding `coverImageUrl` to the data mapping (add `coverImageUrl: c.coverImageUrl` at line ~122)
       - Updating the `DesignerChart` type (or equivalent) to include `coverImageUrl`
       - In `designer-detail.tsx` ChartRow: change the thumbnail check from `chart.coverThumbnailUrl` to `chart.coverThumbnailUrl ?? chart.coverImageUrl`, so it falls back to the full cover image when no thumbnail exists

    3. If the bug is something else (wrong chart thumbnails showing for wrong charts), the investigation will reveal the actual cause. The rendering code maps over `charts` array correctly, so a data ordering issue would be in the query. Add `orderBy: { name: 'asc' }` to the charts relation query if ordering is inconsistent.

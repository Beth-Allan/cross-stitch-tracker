## Interaction Contracts

### Sort Toggle

| Interaction | Behavior |
|-------------|----------|
| Click "Added" | Rows display in insertion order (server default). Button shows active state. |
| Click "A-Z" | Rows sorted alphabetically by supply code using `localeCompare({ numeric: true })`. Button shows active state. |
| Default state | "Added" is active on mount |
| Toggle persists | Sort preference resets on navigation (no persistence -- matches existing behavior) |

Sort toggle visual spec (carried from existing `supplies-tab.tsx`):
- Active: `bg-primary text-primary-foreground rounded-md px-3 py-1.5 text-sm font-medium`
- Inactive: `text-muted-foreground hover:bg-muted rounded-md px-3 py-1.5 text-sm font-medium`
- Container: `flex items-center justify-end gap-1`
- Placement: Above the table, right-aligned

Source: CONTEXT.md D-04, D-05, D-06; existing `supplies-tab.tsx` lines 353-376

### Sort + Table Integration

| Contract | Detail |
|----------|--------|
| Sort responsibility | Parent (SuppliesTab) pre-sorts `SupplyRow[]` arrays before passing to `SupplyTable` |
| SupplyTable awareness | SupplyTable is sort-unaware -- receives already-sorted arrays |
| Sort function | Extracted `sortItems()` logic from old tab: `[...items].sort((a, b) => a.code.localeCompare(b.code, undefined, { numeric: true }))` |

Source: CONTEXT.md D-04, D-05, D-06

### New-Row Entrance Animation

| Contract | Detail |
|----------|--------|
| Trigger | Server action (addThread/addBead/addSpecialty) returns the new junction record ID |
| Signal | ServerActionAdapter stores returned ID and passes as `newRowId` prop (or equivalent) to SupplyTable |
| Animation | CSS class `animate-slide-in`: opacity 0 to 1, translateY -6px to 0, 0.2s ease |
| Cleanup | `newRowId` cleared after animation completes (via `onAnimationEnd` callback or 250ms timeout) |
| Reduced motion | `prefers-reduced-motion: reduce` disables animation (already in `globals.css`) |

Source: CONTEXT.md D-07 through D-10; `globals.css` lines 270-295

### Server Action Feedback

| Event | Feedback |
|-------|----------|
| Supply added successfully | New row appears with slide-in animation. Data revalidated via `router.refresh()` |
| Supply removed successfully | Row disappears. Data revalidated via `router.refresh()` |
| Quantity updated successfully | Value updates in place. No toast (inline editing is low-ceremony) |
| Any server action failure | `toast.error()` with specific message (see Copywriting Contract) |

Source: Established patterns (sonner toast, router.refresh), CONTEXT.md code_context

### CalcParams Derivation

| Param | Source | Fallback |
|-------|--------|----------|
| `fabricCount` | `project.fabric?.count` | 14 |
| `strandCount` | `project.strandCount` | 2 |
| `overCount` | `project.overCount` (narrowed to `1 \| 2`) | 1 |
| `wastePercent` | `project.wastePercent` | 20 |

These are passed as read-only `calcParams` to `SupplyTable`. No settings editing UI in this phase.

Source: CONTEXT.md D-01, D-02, D-03

## States

| State | Visual Treatment |
|-------|-----------------|
| Loading | 3 skeleton rows with pulsing animation (`animate-skeleton-pulse`). Already implemented in Phase 10 `SupplyTable`. |
| Empty (no supplies) | `EmptyState` component with Package icon, "No supplies added yet" heading, descriptive body text. Add row remains visible above. |
| Empty (no project) | Centered text: "No project linked" heading + "Create a project to manage supplies." Already in `project-detail-page.tsx`. |
| Populated | Full table with section dividers, data rows, footer totals |
| Adding (in progress) | Add row shows autocomplete dropdown. `useTransition` provides non-blocking UI during server action call. |
| Server action pending | No explicit loading indicator -- `useTransition` keeps UI responsive. Toast appears only on error. |

## Accessibility

| Concern | Implementation |
|---------|----------------|
| Sort toggle | `aria-pressed` on each button to indicate active sort mode |
| Table structure | Semantic `<table>`, `<thead>`, `<tbody>`, `<th scope="col">` (inherited from Phase 10) |
| Keyboard navigation | Full keyboard flow inherited from Phase 10 add row (type, autocomplete, Enter, Tab, Escape) |
| Status donuts | `<title>` element inside SVG with "X of Y" text (inherited from Phase 10) |
| Delete buttons | Visible on hover; keyboard-accessible via tab order within row |
| Reduced motion | `prefers-reduced-motion: reduce` disables all animations (slideIn, skeleton-pulse, shake) |
| Focus management | After adding a supply, focus returns to the add row search input for continuous entry |

Source: Sketch findings, Phase 10 implementation, design-context.md accessibility section

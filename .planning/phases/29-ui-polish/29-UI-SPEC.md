## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, badge dot gap |
| sm | 8px | Compact element spacing, pill gaps, card body gap |
| md | 16px | Default element spacing, card padding |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps, `space-y-8` sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions: Inherited `5px` cell padding in supply tables (pre-existing, not modified this phase). Badge internal padding uses `px-2 py-0.5` (8px/2px) matching existing `StatusBadge` and `SizeBadge` patterns.

## Typography

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` | Page background, gallery grid background |
| Secondary (30%) | `bg-card` | Gallery card bodies, supply tab card, CalculatorCard |
| Accent (10%) | `text-primary` / `bg-primary` | Active sort pill, primary CTA, CalculatorCard toggle accents |
| Destructive | `text-destructive` | Not used in this phase |
| Selected state | `bg-selected text-selected-foreground border-selected-border` | Active sort toggle button |
| Muted state | `text-muted-foreground bg-muted` | Inactive sort toggle, secondary metadata text |

Accent reserved for: Active sort toggle buttons, CalculatorCard active toggles (Over 1/Over 2), primary interactive controls. Never for badge backgrounds (those use status-specific or size-specific color scales).

## Status Badge Color Update (D-01, D-02)

**Current UNSTARTED config (broken):**
```
bgClass: "bg-muted"
textClass: "text-muted-foreground"
dotClass: "bg-muted-foreground/60"
darkBgClass: ""
```

**Updated UNSTARTED config:**
```
bgClass: "bg-slate-50"
textClass: "text-slate-700 dark:text-slate-300"
dotClass: "bg-slate-500"
darkBgClass: "dark:bg-slate-900/40"
```

Rationale: Matches the pattern used by all other 6 statuses (hue-50 bg / hue-700 text / hue-500 dot / dark:hue-950/40 bg). Slate provides a subtle tinted neutral that reads as intentional, not as "no color assigned." This color dominates gallery views (500+ unstarted charts) so it must be understated.

No changes to the other 6 status entries (KITTING through FFO).

## Digital Copy Indicator (D-05, D-06)

### Data Layer

Add `hasDigitalCopy: boolean` to `GalleryCardData` interface. Derived from:
```sql
_count: { select: { files: true } }
```
Where `hasDigitalCopy = _count.files > 0`.

### Visual Spec

**Placement:** In the card body area, below designer name, as an inline metadata row. Not an overlay on the cover image.

**Layout:**
```
[FileText icon 14px] "Digital copy"
```

**Styling:**
- Icon: `text-primary` (emerald), 14px (`size-3.5`)
- Text: `text-muted-foreground text-xs`
- Container: `flex items-center gap-1` (4px gap)
- Only rendered when `hasDigitalCopy === true`
- Lucide icon: `FileText` (document icon, matches "digital copy" meaning)

**Placement in card body DOM order:**
1. Project name link (existing)
2. Designer name (existing)
3. Stitch count (existing, non-WIP only)
4. **Digital copy indicator (new, conditional)**
5. Genre tags (existing)

**Accessibility:** Icon is decorative (`aria-hidden="true"`). Text provides the semantic meaning.

## CalculatorCard on Project Supplies (D-08, D-09, D-10)

### Placement

Above the supply table in the project detail Supplies tab. Full-width within the tab content area. Same visual card treatment as the chart form's CalculatorCard.

### Component Reuse

Reuse `CalculatorCard` from `src/components/features/charts/form-primitives/calculator-card.tsx`. Same props interface:

```ts
interface CalculatorCardProps {
  calcParams: CalcParams;
  onCalcParamsChange: (params: CalcParams) => void;
  fabricId: string | null;
  onFabricChange: (fabricId: string | null, fabricCount?: number) => void;
  fabricOptions: FabricOption[];
}
```

### Persistence (D-09)

Changes to calculator params persist to the database via server action. Not view-only.

- When user changes strands/over/waste: call server action to update project record
- When user changes fabric selection: call server action to update project's assigned fabric

Use existing `ServerActionAdapter` pattern or create a new server action specific to calc param updates on existing projects.

### Fabric Display (D-10)

- If project has assigned fabric: fabric selector shows that fabric pre-selected
- If no fabric assigned: selector shows available user fabrics as options
- Fabric options come from the same query that currently powers the chart form fabric selector

### Visual Spec

The CalculatorCard's internal layout is unchanged -- it already renders:
- Fabric selector (SearchableSelect)
- Strand count (1-6 EditableNumber)
- Over 1 / Over 2 toggle
- Waste % (EditableNumber)

Spacing between CalculatorCard and supply table below: `space-y-4` (16px).

## File Upload Improvements (D-11, D-12)

### Size Limit (D-11)

| Property | Old Value | New Value |
|----------|-----------|-----------|
| `MAX_FILE_SIZE` | `10 * 1024 * 1024` (10MB) | `50 * 1024 * 1024` (50MB) |
| Error message | "File is too large. Maximum size is 10MB." | "File is too large. Maximum size is 50MB." |

Single-file change in `src/lib/validations/upload.ts`.

### Zip Support (D-12)

Add to `ALLOWED_CHART_FILE_TYPES` (chart files only):
```ts
"application/zip",
"application/x-zip-compressed",
```

Add to `ALLOWED_CHART_FILE_EXTENSIONS`:
```ts
".zip",
```

Do NOT add zip to `ALLOWED_FILE_TYPES` or `ALLOWED_IMAGE_TYPES` -- covers and session photos remain image-only.

No UI changes needed for the file picker. The upload dialog already uses `ALLOWED_CHART_FILE_EXTENSIONS` to build the `accept` attribute.

```
+-----------------------------------+
```

**Status badge (top-left):** Colored background per status. UNSTARTED now slate instead of grey.

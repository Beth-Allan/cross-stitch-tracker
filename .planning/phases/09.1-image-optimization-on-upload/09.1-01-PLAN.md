    **Step 1: Create processAndStoreImage function in upload-actions.ts**

    Add a new exported async function `processAndStoreImage` that:

    1. Accepts `(entityId: string, rawKey: string, category: "covers" | "sessions")` -- entityId is chartId for covers, sessionId for sessions
    2. Calls `requireAuth()`
    3. Fetches the raw image from R2 using `GetObjectCommand` with the `rawKey`
    4. If `response.Body` is null, returns `{ success: false as const, error: "Original image not found in storage" }`
    5. Converts stream to buffer (same pattern as existing `generateThumbnail`)
    6. Runs both Sharp operations in parallel via `Promise.all`:
       - Optimized: `sharp(buffer).resize(OPTIMIZED_MAX_WIDTH, null, { withoutEnlargement: true }).webp({ quality: OPTIMIZED_QUALITY }).toBuffer()`
       - Thumbnail: `sharp(buffer).resize(THUMBNAIL_SIZE, THUMBNAIL_SIZE, { fit: "cover", withoutEnlargement: true }).webp({ quality: THUMBNAIL_QUALITY }).toBuffer()`
    7. Uploads both processed buffers to R2:
       - Optimized key: `{category}/{entityId}/opt-{nanoid()}.webp`
       - Thumbnail key: `{category}/{entityId}/thumb-{nanoid()}.webp`
    8. Deletes the raw original from R2 using `DeleteObjectCommand` with `rawKey`
    9. Returns `{ success: true as const, optimizedKey, thumbnailKey }`
    10. Wraps everything in try/catch -- on failure returns `{ success: false as const, error: "Failed to process image" }` and does NOT delete original

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> R2 (presigned URL) | Untrusted file content uploaded directly to R2 |
| R2 -> Sharp (server) | R2 file content processed through Sharp library |
| server -> R2 (delete) | Server deletes objects from R2 after processing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-9.1-01 | Tampering | processAndStoreImage | mitigate | Sharp validates image format during decode -- corrupt/malicious files cause Sharp to throw, caught by try/catch, raw original preserved (not deleted). No code execution path from Sharp decode. |
| T-9.1-02 | Denial of Service | processAndStoreImage | mitigate | MAX_FILE_SIZE (10MB) already enforced at presigned URL generation. Sharp memory usage for 10MB image is ~50-100MB, well within Vercel's 1024MB limit. Existing timeout guards apply. |
| T-9.1-03 | Information Disclosure | R2 deletion | accept | Raw original deleted after processing. If deletion fails (network error), the raw file persists in R2 but is not publicly accessible (presigned URLs required). Low risk -- same authorization model as before. |
| T-9.1-04 | Spoofing | processAndStoreImage | mitigate | requireAuth() called at entry. Only authenticated users can trigger processing. Category validated by Zod schema at presigned URL generation stage. |
| T-9.1-05 | Elevation of Privilege | confirmUpload field validation | mitigate | VALID_CHART_FIELDS allowlist prevents arbitrary field injection. processAndStoreImage only accepts known category values typed as literal union. |
</threat_model>

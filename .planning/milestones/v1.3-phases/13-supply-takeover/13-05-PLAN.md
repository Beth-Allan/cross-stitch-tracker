**CreationFlowAdapter (creation-flow-adapter.ts):**

The `updateQuantity` method currently does a raw `{ ...row, [field]: value }` spread. When `field === "stitchCount"` and the row is a thread with `isNeedOverridden === false`:

1. Import `calculateSkeins` from `@/lib/utils/skein-calculator`
2. The adapter needs access to calcParams. Add an optional `calcParams` property that can be set/updated externally. Add a `setCalcParams(params: CalcParams)` method to the adapter class. This does NOT change the `SupplyTableAdapter` interface (it's an extra method on CreationFlowAdapter only).
3. In `updateQuantity`, when `field === "stitchCount"` and `row.type === "THREAD"` and `!row.isNeedOverridden` and `this.calcParams` exists:
   ```typescript
   const recalculated = calculateSkeins({
     stitchCount: value,
     strandCount: this.calcParams.strandCount,
     fabricCount: this.calcParams.fabricCount,
     overCount: this.calcParams.overCount,
     wastePercent: this.calcParams.wastePercent,
   });
   const updated = { ...row, stitchCount: value, need: recalculated };
   ```
4. Otherwise, do the existing raw spread.

**ServerActionAdapter (server-action-adapter.ts):**

The `updateQuantity` method needs two changes for stitchCount:
1. Add a `calcParams` property and `setCalcParams` method (same pattern as CreationFlowAdapter).
2. Add a way to know if the row has `isNeedOverridden`. The adapter needs access to the current rows. Add a `setRows(rows: SupplyRow[])` method so the parent can keep the adapter informed of current row state.
3. In the `case "stitchCount":` branch, look up the row from `this.rows` by `junctionId`. If the row exists, is type THREAD, and `!row.isNeedOverridden`, calculate need and send both:
   ```typescript
   mappedData = { stitchCount: value, quantityRequired: recalculatedNeed };
   ```
4. If isNeedOverridden or not a thread, send just `{ stitchCount: value }` as before.

Write RED tests first, then implement.

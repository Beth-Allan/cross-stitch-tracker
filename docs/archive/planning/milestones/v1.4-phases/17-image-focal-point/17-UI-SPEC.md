## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, button icon gap |
| md | 16px | Default element spacing, button padding |
| lg | 24px | Section padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks, minimum touch target |
| 3xl | 64px | Page-level spacing |

Exceptions:
- Focal point marker: 24px diameter (12px radius) for visibility on images
- Edit mode action bar: 8px gap between buttons, 8px padding (compact bar)
- Touch target minimum: 48px for the edit mode trigger button (exceeds accessibility minimum, aligns with spacing scale)

## Color

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` (stone-50) | Page surface behind hero |
| Secondary (30%) | `bg-card` (white) | Hero banner container, action bar bg |
| Accent (10%) | `bg-primary` (emerald-600) | Focal point marker fill, Save button |
| Destructive | `bg-destructive` (red-600) | Not used this phase (no destructive actions) |

Accent reserved for:
- Focal point marker dot/crosshair (the placed indicator)
- "Save" button in edit mode (primary action)
- Ring/focus indicator on the edit-mode trigger button when active

Additional phase-specific colors:
- Crop preview overlay dimming: `black/50` (50% opacity black outside the crop guide area)
- Crop guide border: `white/80` dashed 2px (visible on both dark and light images)
- Marker outer ring: `white` with 2px border (contrast ring for visibility on any image)
- Edit mode backdrop: none (hero image stays fully visible; only crop guide overlays)

## Interaction Contract

### Edit Mode Entry

| # | Action | Result |
|---|--------|--------|
| 1 | User clicks "Set Focal Point" button on hero image | Enter edit mode |
| 2 | Hero image gains cursor-crosshair | Visual affordance for click-to-place |
| 3 | Crop guide overlay appears (4:3 aspect rectangle) | Shows preview of gallery card crop |
| 4 | Action bar appears below image: Save / Cancel / Reset to Center | Commit/abort controls |

### Placing Focal Point

| # | Action | Result |
|---|--------|--------|
| 1 | User clicks/taps anywhere on the hero image | Marker appears at click position |
| 2 | Crop guide repositions around new focal point | Live preview of gallery crop |
| 3 | User can click again to reposition | Marker moves, crop guide follows |
| 4 | Coordinates are normalized 0-1 (relative to image natural dimensions) | Ready for CSS mapping |

### Saving

| # | Action | Result |
|---|--------|--------|
| 1 | User clicks "Save" | Optimistic UI: exit edit mode immediately |
| 2 | Server action persists focalPointX/Y to Chart | Revalidates path |
| 3 | All display contexts update on next render | object-position reflects new point |
| 4 | Toast: "Focal point saved" | Confirmation |

### Cancel / Reset

| # | Action | Result |
|---|--------|--------|
| 1 | "Cancel" — discard unsaved position, exit edit mode | No persistence, revert to prior value |
| 2 | "Reset to Center" — sets value to null | Clears custom focal point |
| 3 | After reset + save: all contexts use default 50% 50% | Browser default centering |

### Error Handling

| # | Scenario | Behavior |
|---|----------|----------|
| 1 | Save fails (network/server error) | Toast: "Couldn't save focal point. Try again." / stay in edit mode |
| 2 | No cover image exists | "Set Focal Point" button not rendered (nothing to anchor) |

| Property | Value |
|----------|-------|
| Shape | Circle with crosshair lines |
| Diameter | 24px |
| Fill | `bg-primary` (emerald-600) at 80% opacity |

## CSS Object-Position Pattern

All `object-cover` image contexts apply focal point as:

```tsx
style={{
  objectPosition: focalPointX != null && focalPointY != null
    ? `${focalPointX * 100}% ${focalPointY * 100}%`
    : undefined  // browser default: 50% 50%
}}
```

Applied to:
- Gallery card `<Image>` (fill + object-cover)
- Spotlight card `<img>` (h-full w-full object-cover)
- Genre/designer detail thumbnails
- Shopping accordion thumbnails

NOT applied to:
- Hero banner (object-contain — no cropping, per D-06)

## Accessibility

| Concern | Solution |
|---------|----------|
| Edit mode trigger | `aria-label="Set focal point for cover image"` (icon-only on mobile) |
| Image click area | `role="button"` + `aria-label="Click to place focal point"` during edit mode |
| Marker | `aria-hidden="true"` (decorative indicator, position described via live region) |
| Live region | `aria-live="polite"` announces "Focal point set at X%, Y%" on placement |
| Keyboard | Enter/Space on trigger enters edit mode; Escape cancels; Tab reaches Save/Cancel/Reset |
| Focus management | On entering edit mode, focus moves to the image click area; on exit, focus returns to trigger |

## Responsive Behavior

| Breakpoint | Behavior |
|------------|----------|
| Mobile (<768px) | Trigger button is icon-only (Crosshair, 48px square). Crop guide scales to 70% of image width. Action bar stacks if needed. |
| Tablet/Desktop (md+) | Trigger button shows icon + label text. Crop guide at 60% width (max 360px). Action bar stays horizontal. |
| Hero max-height | Mobile: 160px, md: 192px, lg+: 256px (existing constraints — edit mode respects these) |

## State Management

| State | Type | Scope |
|-------|------|-------|
| `isEditMode` | `useState<boolean>` | FocalPointEditor component |
| `pendingPoint` | `useState<{x: number, y: number} | null>` | FocalPointEditor (unsaved position) |
| `isPending` | `useTransition` | Save action loading state |
| `focalPointX/Y` | Server data (props) | Passed down from page query |

Optimistic UI: On save, immediately exit edit mode and update local display. If server action fails, re-enter edit mode with the pending point restored and show error toast.

# Cross-Stitch Tracker — Maintenance Ledger

**Status:** Seeded 2026-08-16 at workflow-overhaul step 2, from the ~90-item `999.x` backlog that
lived in CLAUDE.md until step 1 rewrote it (the full original list is in git history at commit
`2860057`, `CLAUDE.md` §Backlog).

**What this is:** the home for **pre-existing warts** any session notices but must not fix
mid-item — warnings, deprecations, flaky behavior, stale config, dead code, silent failures, odd
errors. **Noticing creates an obligation to log here**; the phrase "pre-existing, ignoring" is
banned (hard rule 7). The honest sentence is _"pre-existing — not mine to fix mid-item, logged
for `/cleanup`."_ Fixing unrelated code mid-item is equally forbidden; silence about it is too.

**What this is not:** a feature backlog. Wishes go to `docs/process/work-log/backlog.md`;
contradictions go to `docs/process/work-log/drift.md`; briefed work goes to
`docs/process/build-plan.md`. Keeping those separate is what makes the read-whole rule below
survivable — a ledger holding ~90 mixed items is one nobody reads.

**Entry format:** one row — date · where (path or surface) · what (one plain statement, with
enough of the _why_ that a future session can act without re-deriving it) · noticed by. Append
only.

**The three states.** **Open** — still owed; each row says which item will close it or why it
waits. **Accepted** — Beth ruled it not worth work, so no session re-triages it (a _fresh
instance_ of the same shape is still a new row). **Resolved** — the row stays in this file
verbatim under Resolved until an archive file is warranted. **Rows are never deleted.**

**Read the live ledger whole, every session** — that is what keeping it small is for.
`/cleanup` triages it with Beth: trivial-batch · own-fix-item · accept-and-record. Approved
batches become their own `fix/` branch, never code in the cleanup PR.
